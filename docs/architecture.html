Storefront in a Box: architecture

A small shop's catalog becomes an Alexa+ add-on: a self-hosted MCP server (spec 2025-11-25, Streamable HTTP) with MCP Apps cards, OAuth 2.1 + PKCE account linking and deterministic order rules.
Simulated Alexa+ display

Smart display (Next.js)

  • Push-to-talk (Web Speech API), spoken replies, captions
  • MCP Apps host: renders ui:// cards in a sandboxed iframe via AppBridge
  • Card buttons send ui/message (e.g. "Confirm order MB-4821")
  • Activity panel: tool calls, guardrails, latency
AWS · Strands Agents SDK

/api/assistant

  • Agent + McpClient (Streamable HTTP) → merchant add-on tools
  • OpenAIModel → Qwen3.8-27B (OpenAI-compatible, W&B Inference)
  • BeforeToolCallEvent hooks: purchase confirmation, nut-allergy check, lead time, slot capacity
  • BeforeModelCallEvent step cap · NDJSON event stream
MCP server · spec 2025-11-25

/api/mcp/[merchant]

  • Stateless WebStandardStreamableHTTPServerTransport (JSON responses)
  • Tools: browse_menu, design_cake, check_pickup_slots, get_my_profile, remember_note, prepare_checkout, place_order, order_status
  • MCP Apps resources: menu carousel, cake studio, checkout, live order card
  • HTTP 401 + RFC 9728 metadata for customer tools · Origin check (403)
Deterministic rules

lib/rules.ts

Pricing & tax · pickup windows in shop time zone · 48h custom-cake lead time · decorator capacity per window · tree-nut confirmation. Enforced in the server; pre-checked in Strands hooks.

Storage

Vercel Blob / local files

Orders, customer profiles (notes + usual order = memory across sessions), onboarded merchants.

Merchant

Kitchen screen & onboarding

Live order board with piping messages, status updates that flow back to the customer's order card. Paste a CSV → new add-on endpoint + manifest.

/.well-known/oauth-authorization-server, /oauth/authorize, /api/oauth/token (HMAC-signed tokens)
